## 1. 需求背景与定位
随着 `DayDayUP` 企业级微服务系统的不断完善，后端已实现了基于网关的统一路由鉴权、基于 `daydayup-auth` 的认证机制以及由 `daydayup-admin` 提供的用户、角色和菜单功能。为了能够让管理员与运营人员方便地管理系统，急需建设配套的管理后台前端项目。

本项目的定位为：**企业级通用微服务后台管理前端**。

---

## 2. 核心业务功能需求

### 2.1 登录与身份认证
- **功能描述**: 用户进入系统时，需要能够输入账号密码进行登录。
- **具体要求**:
  - 点击登录后，向网关/认证中心发起 OAuth2.1 授权请求。
  - 登录成功后将返回的 JWT Token 存储，并在全局请求拦截器中携带该 Token，供后端服务提取用户上下文进行安全校验。

### 2.2 动态菜单与权限展示
- **功能描述**: 登录成功后，前端系统根据当前登录用户的权限动态展示菜单，并限制按钮级操作。
- **具体要求**:
  - 系统侧边栏菜单由后端配置数据动态生成。
  - 用户无权访问的路由，前端路由表内不可加载该路径。
  - 对于新增、修改、删除等操作按钮，前端通过自定义权限标识（如 `admin:user:add`）进行无权限时的 DOM 隐藏。

### 2.3 后台管理基础页面
包含以下四个基础功能模块：
1. **用户管理**: 用户账号维护、角色绑定、组织部门划分。
2. **角色管理**: 角色新建、绑定对应菜单与接口权限。
3. **菜单管理**: 路由路径、组件关联名称、按钮权限的树形结构维护。
4. **系统监控（接入扩展点）**: 展示后端微服务健康状态、在线用户。

---

## 3. 非功能性需求与技术指标
- **架构模式**: pnpm Workspace (Monorepo) 多包协作模式，分离底层协议与业务视图。
- **安全性**:
  - 支持敏感接口的请求参数 HmacSHA256 签名机制。
  - 前端路由强拦截，防止未授权用户尝试直接输入 URL 越权访问。
- **性能与体验**:
  - 采用 **Vite** 的局部更新与代码分包，保证首屏加载速度。
  - 整体设计需符合 modern 审美（如支持暗黑模式、合理的间距、柔和的色调）。

## 4. 实施阶段与任务清单 (Implementation Plan & Task List)

本项目工程的搭建与开发将分为三个阶段进行。

| 阶段 | 核心任务 | 具体产出物 |
| :--- | :--- | :--- |
| **阶段 1：工程骨架搭建** | 1. 初始化 `daydayup-ui` 根项目<br>2. 配置 pnpm-workspace 与 TypeScript 规范<br>3. 建立 `packages/shared` 与 `packages/apps/admin-ui` 目录结构 | `pnpm-workspace.yaml`<br>`package.json`<br>工程依赖关系就绪 |
| **阶段 2：公共底座与拦截器** | 1. 封装 Axios 网络请求模块<br>2. 实现 Request 自动注入 Token<br>3. 引入 Crypto-JS 编写接口加签公共方法 | `packages/shared/src/api` 下的网络逻辑代码 |
| **阶段 3：管理后台业务开发** | 1. 引入 Element Plus 与 Pinia<br>2. 编写全局路由守卫与动态路由加载逻辑<br>3. 编写登录页与 Layout 骨架结构 | `admin-ui` 可交互的管理后台界面与动态菜单 |

## 5. 验收标准
1. 在项目根目录下执行 `pnpm install` 能够成功安装所有 workspace 包依赖。
2. 执行 `pnpm --filter @daydayup/admin-ui build` 能够成功无错打包出静态 dist 文件。
3. 动态路由机制正常生效，模拟无菜单权限的用户登录时，侧边栏不显示未授权菜单且直接输入路径展示 403。
