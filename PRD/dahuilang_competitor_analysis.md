# 大灰狼聚合平台竞品考察与阅读中台 Gap 分析

> 日期：2026-07-09  
> 范围：记录已考察的公开站点、用户中心、书源/软件/管理/监控、聚合阅读 API、能力矩阵与 DayDayUP 阅读中台差距。  
> 安全说明：本文只记录字段结构、接口形态和产品能力，不保存明文 Cookie、`qttoken`、`deviceId` 或任何可复用登录凭据。

## 1. 竞品形态概览

“大灰狼聚合”由两类入口组成：

| 入口 | 定位 | 已观察能力 |
| ---- | ---- | ---- |
| `http://219.154.201.122:5006/user` | 认证中心、用户中心、书源/软件分发、用户自助管理、系统监控 | 用户资料、会员密钥、阅读统计、在线设备/IP、书源包、客户端软件下载/注册码、系统资源状态 |
| `api.langge.cf` | 公开聚合阅读 Web 应用/API | 搜索、发现、详情、目录、正文、下载、书架等聚合阅读能力 |

竞品核心闭环：充值会员 -> 获得 `user_key`/密钥 -> 在阅读类客户端导入书源或填写密钥 -> 访问多源聚合内容 -> 正文访问时记录在线状态与阅读次数 -> 通过 IP/设备上限、封禁、日志治理密钥共享。

## 2. 用户中心能力

用户中心主要页签包括：用户、书源、软件、管理、监控。

### 2.1 用户模型

已观察用户字段结构：

| 字段 | 含义 |
| ---- | ---- |
| `id` | 用户 ID |
| `email` | 登录邮箱 |
| `user_key` | 阅读客户端使用的密钥/会员 Key |
| `is_vip` / `vip_level` | 会员状态与等级 |
| `vip_start_time` / `vip_end_time` | 会员有效期 |
| `balance` | 余额 |
| `day_read_count` / `all_read_count` | 当日/累计阅读次数 |
| `last_read_time` | 最近阅读时间 |
| `device` | 设备信息 |
| `ban_count` / `is_banned` | 封禁次数/是否封禁 |
| `ban_time` / `unban_time` | 封禁/解封时间 |
| `user_ip` | 最近或当前访问 IP |
| `register_time` | 注册时间 |

### 2.2 会员与防共享

- 正文访问是防共享的主控制点：访问正文即视为在线。
- 10 分钟未访问正文自动下线。
- 普通/VIP 最多 1 个 IP 同时阅读；SVIP 最多 5 个 IP。
- 通过在线 IP/设备、阅读次数、封禁状态形成密钥治理闭环。

对 DayDayUP 的启发：会员密钥不是单纯鉴权字段，而是“正文访问限流 + 在线状态 + 风控审计”的产品闭环；应作为 P1 产品化能力，不应塞入当前基础抓取切片。

## 3. 书源与软件分发生态

### 3.1 书源分发

竞品按客户端生态拆分书源包：

- 阅读 / 源阅 / 栖阅 / 阅读越多
- iOS 用心读书
- 读不舍手 / 千阅 / 源阅读
- 益达
- 香色闺阁
- 轻悦时光

书源包按普通/VIP、完全版/独立版/兼容版区分，并支持协议导入：

- `yuedu://booksource/importonline?src=...`
- `legado://import/auto?src=...`

### 3.2 软件分发

软件分发覆盖 Android 阅读、iOS TestFlight/付费客户端、阅读阅多、读不舍手、栖阅、轻阅读全平台，并通过 `/qyd` 类接口分发注册码。

对 DayDayUP 的启发：书源分发中心应优先服务“规则包版本化、更新日志、客户端导入入口”，而不是复刻竞品的多客户端软件下载站。第一阶段先不做公开客户端分发。

## 4. 管理与监控能力

管理页包含：

- 头像/昵称与基础资料
- 番茄登录
- 在线 IP/设备自助管理
- 修改密码
- 联系方式/教程

监控页通过 `/api/system_info` 暴露 CPU、内存、存储、网络上下行、上下行速率等指标。

对 DayDayUP 的启发：P2 可提供轻量用户中心和健康状态页，面向运营/自用可见，不需要第一期引入复杂权限中心或公开商业门户。

## 5. 聚合阅读 API 观察

已观察公开聚合阅读 API 类型：

| API | 能力 |
| ---- | ---- |
| `/search` | 聚合搜索 |
| `/discovestyle` | 发现页样式/分类 |
| `/discovedata` | 发现页数据 |
| `/detail` | 作品详情 |
| `/catalog` | 目录 |
| `/content` | 正文 |
| `/download` | 下载 |
| `/downloadImg` | 图片下载 |
| 书架相关接口 | 收藏/书架能力 |

`/search` 统一信封包含：

```json
{
  "code": 0,
  "msg": "ok",
  "cache": false,
  "time": 123,
  "source_time_cost": {
    "sourceA": { "time": 80, "cache": false, "count": 10 }
  },
  "disabled_sources": [],
  "data": []
}
```

关键启发：`source_time_cost` 将每个来源的耗时、缓存命中、结果数量暴露给调用方或运营侧，是多源聚合平台的基础可观测能力。

## 6. 能力矩阵与 DayDayUP Gap

| 能力 | 竞品现状 | DayDayUP 现状/规划差距 | 建议优先级 |
| ---- | ---- | ---- | ---- |
| 多源聚合搜索 | 已提供公开 `/search`，含 per-source 耗时与禁用源 | 已有基础阅读 API 与可观测切片，但需重新规划为平台自研聚合编排，不再以直接导入开源书源并执行为主线 | P0/P1 |
| per-source 可观测 | `source_time_cost`、禁用源、缓存标记 | 需要在 API/运营侧形成稳定契约 | P0/P1 |
| 会员密钥 | `user_key` 与 VIP 等级绑定 | 当前 PRD 未系统纳入密钥生命周期与访问治理 | P1 |
| 正文访问限流 | 正文访问即在线，按 IP/等级限流 | 需要围绕正文 API 建立限流、在线会话、审计 | P1 |
| 规则包分发 | 多客户端、多版本书源包与协议导入 | 应转化为 DayDayUP 自研规则包/源配置分发，不直接复刻外部书源执行模型 | P1/P2 |
| 轻量用户中心 | 用户资料、阅读统计、设备/IP 管理 | 可作为运营/自助页演进 | P2 |
| 服务/书源健康 | 系统资源监控、部分接口日志 | 需补服务健康、书源健康、禁用源列表 | P2 |
| 多内容形态 | 小说、听书、短剧、漫画 | DayDayUP 第一期仍只做文字小说；多形态作为远期扩展 | P3 |
| 客户端下载/EPUB | 软件分发、下载接口 | 非第一期重点 | P3 |

## 7. 对 DayDayUP 新方案的产品启发

1. 目标应从“导入开源阅读书源并逐条解析”调整为“自研高性能小说聚合搜索与阅读平台”。
2. 开源阅读书源只作为字段命名、接口入口、URL 模板、站点覆盖面的参考素材；平台自行完成解析、拆解、合并、净化、广告移除、质量评估与资产化。
3. 核心能力顺序应为：多源编排与可观测 -> 内容解析/净化资产化 -> 正文访问限流与会员密钥 -> 规则/源包分发 -> 用户中心与健康状态。
4. 第一阶段必须守住文字小说 API 中台边界，不扩展漫画、听书、短剧正文能力，不建设复杂权限中心或公开商业化门户。

## 8. 推荐里程碑/交付切片

| 阶段 | 目标 | 关键交付 |
| ---- | ---- | ---- |
| M0 | 新架构与契约重定稿 | 明确“自研聚合平台”路线、废弃“直接导入执行开源书源”作为主线；更新 PRD/spec |
| M1 | 多源聚合编排与 per-source 可观测 | 搜索编排器、源适配器抽象、`source_time_cost`、禁用源、降级策略 |
| M2 | 自研解析与内容资产化 | 详情/目录/正文抽取、章节/作品合并、raw/normalized/sanitized 三层资产 |
| M3 | 高性能缓存与高可用 | 热门搜索/目录/正文缓存、异步补抓、单源故障隔离、限速/熔断 |
| M4 | 会员密钥与正文访问限流 | `user_key` 生命周期、正文访问会话、IP/设备限流、阅读统计、封禁审计 |
| M5 | 规则包/源配置分发中心 | 自研源配置版本、更新日志、客户端导入入口、兼容协议链接 |
| M6 | 轻量用户中心与健康状态 | 用户自助信息、在线 IP/设备、服务健康、书源健康状态页 |
| M7 | 远期扩展 | 多内容形态、客户端下载、EPUB/下载等能力 |
